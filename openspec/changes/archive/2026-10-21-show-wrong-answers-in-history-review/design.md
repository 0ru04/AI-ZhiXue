# Design

## Context

微信小程序历史复盘页通过 `GET /api/v1/user/quizzes/{quiz_id}` 获取 `QuizHistoryDetail`。当前响应已经包含 `questions`、`answer_records` 和 `report`；题目数据包含 `stem`、`options`、`answer`、`explanation`，作答记录包含 `question_id`、`selected_answers` 和由服务端计算的 `is_correct`。页面现有“答题记录”区域会展示全部作答，但本次新增的错题复盘需要独立、可快速定位的呈现。

历史复盘页仅在 `TARO_ENV === 'weapp'` 时注册和展示，本次设计继续沿用该平台边界。H5 与即时报告页不参与本次数据流。

## Goals / Non-Goals

**Goals:**

- 在历史复盘详情内增加独立的“本次错题”区域。
- 从现有题目与作答记录派生错题视图，展示题干、用户答案、正确答案和解析。
- 在全部答对时展示明确空状态。
- 用现有接口和现有持久化结构完成功能，不产生迁移。

**Non-Goals:**

- 不修改即时 `pages/report` 页面。
- 不新增跨闯关错题本、错题重练或掌握度统计。
- 不修改报告生成逻辑、评分逻辑、登录逻辑或 H5 用户系统。
- 不删除现有“答题记录”区域；本次采用新增独立区域的方式保留原有完整作答回看能力。

## Decisions

### 1. 在现有答题记录之前新增独立错题区域

在历史复盘详情的“答题记录”区域之前增加“本次错题”面板，错题数据由当前详情响应即时派生。这样用户先看到最需要复习的内容，同时保留现有全部作答记录，避免破坏已有回看能力。

备选方案是把现有“答题记录”直接改成仅显示错题。该方案页面更精简，但会移除已答对题目的历史回看，属于未请求的行为收缩，因此不采用。

### 2. 客户端按 `question_id` 关联并按服务端 `is_correct` 筛选

页面先建立 `questionById` 映射，再从 `answer_records` 中筛选 `is_correct === false` 的记录。答题是否正确继续以服务端持久化的 `is_correct` 为准，不在客户端重新比较答案，避免前后端判定规则分叉。

备选方案是在前端根据 `selected_answers` 与 `question.answer` 重新判错。该方案会增加重复规则，并可能让历史数据与报告统计不一致，因此不采用。

### 3. 统一格式化选项标识和文本

用户答案与正确答案通过同一格式化函数转换：按题目 `options` 顺序输出 `选项标识. 选项文本`；无法匹配的旧数据回退显示原始标识；没有有效用户选项时显示“未作答”。题干与解析直接使用题目中的 `stem` 与 `explanation`。

备选方案是只显示选项字母或只显示文本。只显示字母需要用户来回对照选项，只显示文本在重复语义下不够精确，因此采用标识与文本并列。

### 4. 复用现有视觉体系并增加局部样式

新区域复用历史复盘页已有的 `panel`、标题、分隔线和颜色变量，不引入新组件或依赖。每条错题使用带序号的内容块，用户答案、正确答案和解析各自独占一行；全部答对时显示带明确文字的占位内容，而不是隐藏整个区域。

### 5. 不新增或扩展后端接口字段

现有 `QuizHistoryDetail` 已包含完成本次展示所需的全部字段，后端实现保持原响应结构。实施时只增加接口契约回归断言，锁定历史详情必须返回题目解析、正确选项、用户选项和服务端判错结果。

备选方案是新增 `wrong_questions` 数组。该字段只会重复现有数据，并增加接口兼容与持久化维护成本，因此不采用。

## Risks / Trade-offs

- **错题内容与现有答题记录重复**：新区域会再次展示错题信息，但不影响数据正确性；通过标题和视觉层级区分“错题复盘”与“完整作答记录”，优先保证快速复习和向后兼容。
- **历史数据可能缺少解析或题目映射**：展示层对缺失解析显示“本题暂无解析”，对无法关联的题目不阻塞页面其他区域渲染；服务端契约测试覆盖当前新数据的完整性。
- **客户端依赖服务端 `is_correct`**：若历史记录被错误写入，前端无法自行纠正；继续以服务端结果为准，并通过现有持久化逻辑与契约测试降低风险。
- **现有 API 模型使用通用字典承载题目和记录**：前后端类型约束不对等；本次不扩大改动范围，仅用契约断言和前端防御性取值降低兼容风险。

## Migration Plan

无数据库迁移和接口版本迁移。发布时先确认现有历史详情接口响应字段完整，再随微信小程序版本发布页面改动；若页面出现问题，可回滚历史复盘页组件与样式，不影响已持久化的闯关、作答和报告数据。
